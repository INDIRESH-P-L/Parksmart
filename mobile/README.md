# ParkSmart — Mobile (Flutter)

The Flutter client for ParkSmart. It talks to the **same `/api/v1` backend** as the
web app (Express + Supabase / built-in local DB), with the same green "Liquid Glass"
look — frosted `BackdropFilter` cards, a drifting gradient blob background, and Hero
shared-element transitions.

## Screens

Splash · Login · Register · Home/Dashboard · Parking Map (OpenStreetMap via
`flutter_map`) · Slot Details (walking distance from your location) · Book Slot (live
price preview) · My Bookings · Active Ticket / Wallet (full-screen QR for the gate) ·
Profile · Admin Dashboard · **QR Scanner** (admin/operator gate check-in/out).

## Prerequisites

- Flutter SDK **3.22+** (Dart 3.4+) — <https://docs.flutter.dev/get-started/install>
- Android Studio / Android SDK (for the emulator + APK build)
- The ParkSmart backend running (see the repo root `README.md`).

## 1 · Generate the native platform folders

This repo ships `lib/`, `pubspec.yaml`, and `assets/`. The `android/` and `ios/`
folders are generated by Flutter (they're environment-specific, so they aren't
committed). From `mobile/`:

```bash
flutter create --org com.parksmart --platforms=android,ios .
flutter pub get
```

`flutter create` only fills in missing files — it will **not** overwrite `lib/`,
`pubspec.yaml`, or `assets/`.

## 2 · Grant the native permissions

After `flutter create`, add these so the camera (QR scan), notifications, location
(walking distance), and cleartext HTTP to a local backend work.

**`android/app/src/main/AndroidManifest.xml`** — inside `<manifest>`, above
`<application>`:

```xml
<uses-permission android:name="android.permission.INTERNET"/>
<uses-permission android:name="android.permission.CAMERA"/>
<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"/>
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION"/>
```

…and on the `<application>` tag add `android:usesCleartextTraffic="true"` (lets the
app reach `http://10.0.2.2:5000` in development; drop it for an HTTPS production API).

**`ios/Runner/Info.plist`** — add:

```xml
<key>NSCameraUsageDescription</key>
<string>Scan parking QR tickets at the gate.</string>
<key>NSLocationWhenInUseUsageDescription</key>
<string>Show walking distance to your parking slot.</string>
```

`mobile_scanner` needs Android `minSdkVersion` 21+ — Flutter's default (flutter.minSdkVersion)
already satisfies this.

## 3 · Point the app at your backend

The API base URL is a compile-time define (defaults to the Android-emulator host
`http://10.0.2.2:5000/api/v1`, which reaches the backend on your machine's
`localhost:5000`).

```bash
# Android emulator (default — no flag needed)
flutter run

# Physical device on the same Wi-Fi: use your machine's LAN IP
flutter run --dart-define=API_URL=http://192.168.1.20:5000/api/v1
```

Sign in with the seeded accounts (same as web):

| Role     | Email                 | Password       |
| -------- | --------------------- | -------------- |
| Admin    | `admin@sece.ac.in`    | `Admin@123`    |
| Operator | `operator@sece.ac.in` | `Operator@123` |
| User     | `user@sece.ac.in`     | `User@123`     |

(The login screen is pre-filled with the demo user for convenience.)

## 4 · Build a release APK

```bash
flutter build apk --release --dart-define=API_URL=https://YOUR_API_HOST/api/v1
```

The APK is written to `build/app/outputs/flutter-apk/app-release.apk`.
For a smaller, per-ABI split: `flutter build apk --release --split-per-abi`.

## Architecture

```
lib/
├── config/app_config.dart        # env-style base URL (--dart-define)
├── models/                       # User, ParkingSlot, Booking, Availability, …
├── services/                     # api_service (dio) → auth/parking/booking/admin/notifications
├── providers/                    # ChangeNotifier state (auth, parking, booking)
├── widgets/                      # GlassCard, BlobBackground, ParkingCard, BookingCard, …
├── screens/                      # splash, auth, dashboard, map, slot, booking, ticket, profile, admin, scanner
├── routes/app_routes.dart
└── main.dart                     # MultiProvider + MaterialApp (dark theme)
```

Networking mirrors the web client: a single `ApiService` (Dio) injects the JWT from
`SharedPreferences`, unwraps the `{ success, data, message }` envelope, and surfaces
the backend's friendly error messages.
